# /run-test — 自然语言全流程测试（管线1）

## 测试新需求

```
你: 测试新需求，地址 http://xxx，手动登录
我: 遵循以下流程自动执行
```

> 管线1已通用：需求文档放 `docs/`（或项目目录），URL/api_base 全参数化，可复测不同项目。

## 测试流程

### 第一步：需求分析

```
读取需求文档，提取:
  - 功能点清单
  - 输入框及校验规则（边界值 + 异常值）
  - 操作流程（主路径 + 分支路径）
  - API 接口列表
  - 状态变化
  - NOT/负面约束
```

### 第二步：生成测试矩阵

针对每个输入框生成：

```
正常值:   符合规则的有效输入
边界值:   最小值、最大值、临界值
异常值:   格式错误、超长、特殊字符
空值:     空字符串、仅空格
```

针对每个操作生成：

```
主路径:   正常操作流程
异常路径: 失败、超时、重复操作
状态变化: 操作前后的 UI + API 数据对比
```

### 第三步：执行测试

```
1. browser_navigate → 打开页面
2. 等待手动登录
3. 逐条执行测试用例:
   a. 操作界面
   b. browser_network_requests → 捕获 API 请求/响应
   c. browser_evaluate → 验证 UI 状态
   d. browser_take_screenshot → 截图留证
```

### 第四步：输出报告

```
每项标注: 通过 ✅ / 失败 ❌ / 无法验证 ⚠️
含: 测试点 | 预期 | 实际 | API 数据 | 结论
```

## 测试矩阵规则

### 输入框校验

| 类型 | 规则 |
|------|------|
| 正常值 | 需求中定义的合法输入 |
| 边界最小值 | 合法最小值 / 合法最小值-1 |
| 边界最大值 | 合法最大值 / 合法最大值+1 |
| 格式校验 | 不符合格式要求的值 |
| 特殊字符 | HTML标签、SQL注入、脚本 |
| 空值 | 空字符串、纯空格 |

### API 验证

| 验证点 | 方式 |
|--------|------|
| 请求参数 | browser_network_request 查看请求体 |
| 响应数据 | browser_network_request 查看响应体 |
| UI/API 一致性 | 页面显示 vs API 返回数据对比 |
| 状态变化 | 操作前后的 API 数据对比 |

### 状态与流程

| 类型 | 覆盖 |
|------|------|
| 主流程 | 正常操作到完成 |
| 分支流程 | 取消、返回、跳过 |
| 异常流程 | 错误提示、空状态、禁用状态 |
| 前置条件 | 未满足条件时的拦截提示 |
