# 测试矩阵提取规则

每次读取新需求文档时，按以下规则提取测试点。

## 1. 识别输入框

对每个输入框生成：

```
TC-BOUNDARY-xxx  字段名 — 最小值/最大值/格式
TC-ERROR-xxx     字段名 — 空值/特殊字符/超长
```

| 需求描述 | 生成的测试用例 |
|---------|--------------|
| "姓名：2-20 个字符，仅支持中文及·" | 1字(拒)、2字(通)、20字(通)、21字(拒)、含数字(拒)、含英文(拒)、含<script>(拒)、空(拒) |
| "身份证号：18 位" | 17位(拒)、18位(通)、19位(拒)、含X(通)、含特殊字符(拒) |
| "提现金额：100的倍数，最低1000" | 999(拒)、1000(通)、1001(拒)、1050(拒)、1100(通) |

## 2. 识别按钮/操作

对每个操作生成：
- 主路径：正常操作流程（TC-FUNC-xxx）
- 前置条件：未满足条件时按钮状态（TC-FLOW-xxx）
- 重复操作：已执行后的状态变化

## 3. 识别状态变化

对每个状态字段生成：
- 初始状态
- 操作后状态
- 反向操作后状态（如：驳回后积分退回）

## 4. 识别 API 接口

从需求描述中推断后端接口，生成 API 验证用例（TC-API-xxx）：
- 请求参数格式
- 响应数据结构
- UI 与 API 数据一致性

## 5. 识别负面约束

需求中的 NOT / 不应 / 禁止 → TC-NEGATIVE-xxx
