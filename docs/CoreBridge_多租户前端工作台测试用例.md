## 三、 u-X 同账号跨租户隔离交叉验证（新增，测试重点）

**背景**：u-X 为同一用户绑定多个租户（租户1 + 租户2），本组用例专门验证「**同一账号切换租户时数据按租户隔离**」——这是多租户隔离测试的重中之重。

> 账号参数：u-X userId/用户名、workbenchId/appId 真实值见 `projects/corebridge/.env.example`（占位 `CB_UX_*` 变量）；结构上按斜杠划分，**第一个 workbenchId 对应第一个 appId**（租户2 在前、租户1 在后）。

## 四、 文件隔离接口补测（新增）

**背景**：用于判定 TC-ISO-14/UX-06 的「文件直链可访问」是**应用层隔离绕过（真漏洞）**还是 **presigned URL 链接保密风险（标准模式）**——验证 u-B 能否不靠「tester 递链接」，仅通过应用接口拿到 u-A 的文件。

| 用例ID | 所属模块 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| FILEDL | 文件隔离接口补测 | u-A 已上传文件（有 fileId） | u-A 上传捕获 fileId → 退出 → u-B 登录 → 用 u-A 的 fileId 依次调用候选下载接口 | 其余候选路径（`/files/download`、`/files/get`、`/files/raw` 等）在项目中**未使用**（404）；真实下载接口见 FILEDL2 | P0 |
| FILEDL2 | 文件隔离接口补测 | u-A / u-X 已上传文件 | **真实置换接口** `GET /mc/api/v1/agentcore/files/{fileId}`：① 属主 u-A 用自己 fileId + 自己 token 调用；② u-B（跨用户）用 u-A 的 fileId + u-B token 调用；③ u-X 租户2 上传 → u-X 租户1 用租户2 的 fileId + 租户1 token 调用 | 属主→200 返回 `{data:{rawUrl,fileName}}`；u-B 跨用户→404「文件不存在」；u-X 同账号跨租户→404「文件不存在」→ **应用层文件隔离有效** | P0 |
